# 家具比例調整記錄（v0.6 → v0.6.1）

## 回報問題
1. 整體家具看起來太小、高度太低（矮胖感）。
2. 茶几看起來懸空，桌腳沒有站在地上。

## 原因確認
1. **垂直被壓扁**：等角投影 `iso()` 的 z 原生 1:1，而格子在螢幕上是寬菱形，
   家具高度（z 2~3 單位）相對寬度（4~5 單位）天生顯矮。
   另 `footprint` 容器比例與本體比例不一致時，`preserveAspectRatio="meet"`
   會留白壓縮（例：v0.6 沙發 212×112 框只渲染出 112px 寬的圖）。
2. **懸空**：兩個疊加原因 —
   - CSS `.floor-shadow` 固定在容器 68% 高度，但桌腳底（z=0）落在圖的底部，
     陰影與腳對不上，中間出現空隙；
   - 茶几桌腳只有 0.28 單位粗、視覺支撐不足。

## 調整（warm-home/src/modules/furnitureArt.js）
- 新增 `Z_SCALE = 1.32`：投影時 `y = (x+y)*0.5 - z*1.32`，全家具等比拉高。
- 新增 `p.ground(cx, cy, r)`：在 z=0 地面畫等角接地橢圓（rx=r×0.866、ry=r×0.5），
  每件地板家具第一個繪製（墊底），陰影永遠跟著腳走。
- 茶几桌腳 0.28 → 0.34 加粗。
- `FurnitureItem.js` 移除對不準的 CSS `.floor-shadow`，只用圖內接地陰影。

## 尺寸公式（warm-home/src/modules/furniture.js）
`footprint.w = round((gw+gh) × 34)`，`footprint.h = round(w ÷ 本體實測比例)`。
本體比例以 `node aspect-tmp.mjs`（暫存腳本，用完即刪）實測 viewBox 得出：

| 家具 | 佔位 | 實測比例 | footprint（舊→新） |
|---|---|---|---|
| 床 | 4×3 | 1.039 | 210×194 → 238×229 |
| 沙發 | 3×1 | 0.929 | 120×122 → 136×146 |
| 書桌 | 3×1 | 0.953 | 120×120 → 136×143 |
| 植物 | 1×1 | 0.868 | 60×66 → 68×78 |
| 立燈 | 1×1 | 0.819 | 60×69 → 68×83 |
| 椅子 | 1×1 | 0.839 | 60×67 → 68×81 |
| 杯桌 | 1×1 | 0.824 | 60×67 → 68×83 |
| 搖椅 | 1×1 | 0.836 | 60×65 → 68×81 |
| 茶几 | 3×1 | 1.028 | 120×112 → 136×132 |
| 畫框 | 2×1 | 1.269 | 90×71 → 102×80 |
| 時鐘 | 1×1 | 1.000 | 60×60 → 68×68 |
| 窗戶 | 2×1 | 1.350 | 90×67 → 102×76 |
| 春聯 | 1×1 | 0.825 | 60×72 → 68×82 |

容器比例＝本體比例 → 本體 100% 填滿，不再留白縮小。

## 後續再調只需三步
1. 改 `DRAW` 裡該件家具 → 2. 跑暫存腳本量新比例 → 3. 按公式改該件 `footprint`。
   `Z_SCALE` 則是全域開關，動它之後 13 件比例都要重測。

## v0.7.3 刷新不一致＋降級

## v0.7.2 懸空真因：框架留白（問答記錄）
- 問：家具底部跟地板座標什麼關係？
  答：容器底（含錨點）釘在佔位格正中（`-100%`），本體底（腳＋接地影）本該貼著它。
- 問：框架跟實際底部什麼關係？
  答：SVG viewBox 的 `pad = 6` 在等角單位下等於半個框——本體只佔框 38%
  （床框 19.3 寬、本體 7.3），腳離錨點差了三分之一框高，全部懸空是必然的。
- 修法：`pad` 6 → 0.4，本體佔框 90%+；13 件按新實測比例重算
  （床 238×217、沙發 136×166 … 時鐘 68×68 不變）。
- 下次量測直接看 viewBox：本體寬佔比 <80% 就是又飄了。

## v0.7.1 啟動崩潰（object is not iterable）
- 現象：push 後開 App 直接「目前無法啟動」。
- 根因：`cornerPolygons()` 多邊形陣列混入 `{x,y} 物件`（O、TOP），
  `.map(([x,y]) => …)` 解構物件炸裂。共三處：leftWall、rightWall、floor、trimRight。
- 修法：統一先轉 `[x, y]` 陣列點。
- 防再犯：verify 加「房體多邊形 4 點全是數字」＋「VIEW 10:15」兩項，
  CI 會擋（這次就是 verify 先抓到第二處漏網）。

## v0.6.6 滿版＋尺寸統一（10:15、格子單位）
- 發現大 bug：容器直式 3:4、畫布橫式 800×600，SVG letterbox 只佔中間一半，
  家具百分比定位全錯位（手機上差 40px 起跳）——之前以為的「飄」主因是這個。

## v0.6.5 泡泡換行＋茶几飛起
- 泡泡 2~3 字就換行：泡泡寬被家具盒寬夾住（小家具盒才 88px）。
  修法：`width: max-content; max-width: 122px`，約 6 個中文字換行，不受盒寬影響。
- 茶几飛起：地板錨點 `translate(-50%,-72%)` 讓腳落在格心下約三格遠，
  看起來跟格子脫鉤。修法：地板改 `-100%` 腳落地（腳＝格心），牆飾維持 `-50%` 置中；
  點選判定的視覺中心同步分平面計算。

## v0.6.4 點選失準（虛線框太大）
- 現象：家具放大後盒子大＋互疊，點下去常選到上面那件、不是想點的。
- 修法（`RoomScene.js`）：viewport capture 統一攔截點擊，只考慮「點落在盒內」的，
  選離中心最近的一件；點空地取消選取；❗事件與工具列按鈕維持原行為；
  剛拖完的點擊照舊吞掉。
- 選取視覺：大虛線外框 → 金色光暈（`drop-shadow` 跟著本體透明度走，貼著圖）。
- 若之後還是難點：把判定式裡的盒半徑 `hw/hh` 乘 0.8 縮小，或只取中心 60px 內。

## v0.6.3 高度卡住事件（顯示 bug）
- 現象：怎麼調高度都沒變化。
- 根因：`contentPack.ensureDefaultFurniture` 對已存在的型錄永遠沿用
  `cur.footprint`，v0.6.1/v0.6.2 的放大只對新安裝有效；且圖拉高後框沒跟著換，
  `meet` 留白把圖壓得比 v0.6 更小。
- 修法：內建款（`builtin !== false`）每次啟動以程式碼為準全量刷新；
  自訂款（管理員 JSON，`builtin:false`）永不覆蓋。
- 順帶稽核：拖曳位移有角落規則覆蓋（specificity 高）無礙；`.furniture__body` 等
  死 CSS 無害，暫不動。
